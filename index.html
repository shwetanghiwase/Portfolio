RAG assistant for an airline reliability programme manual

Reliability engineers lose time searching long programme manuals for alert-level rules, deferral limits and reporting deadlines. This assistant retrieves the relevant manual section, answers only from that section, cites it, and refuses when the manual doesn't cover the question.

Answers appear here with the cited manual section, retrieval scores and response time.

How it works

  • Ingest: the manual is split into 14 section-sized chunks, each with a section ID.
  • Retrieve: BM25 ranking over the chunks. v2 adds an aviation abbreviation dictionary (MEL, AOG, PIREP, MTBUR…).
  • Answer: extractive. The assistant quotes the best-matching sentences from the top section and cites it, so it can't hallucinate content.
  • Guardrail: if the top score is below the confidence threshold, it refuses and routes the question to the Reliability Engineer.

The corpus is a synthetic manual for a fictional operator ("Northwind Regional"), written for this prototype. It isn't a real airline or regulatory document. Production next step: swap extractive answers for an LLM constrained to the retrieved chunks, keeping the same eval set (Project 3).

Post-mortem: v1 retriever failed on aviation abbreviations

Engineers write "MEL", "AOG" and "PIREP". The manual mostly spells them out. The v1 keyword retriever couldn't connect the two, so it either retrieved the wrong section or refused a valid question. Switch the selector on Project 2 to v1 and ask "What is the MEL Cat C limit?" to see it.

StepFinding
What went wrongv1 passed every question written in full words, then failed the abbreviation questions in the golden set (exact count shown above, measured live).
Why we missed itThe first test questions were written by me while reading the manual, so they reused the manual's wording. Real users don't. The test set was biased towards the corpus.
Fix(1) Abbreviation dictionary applied to the query before retrieval. (2) Golden set rewritten so half the questions use the shorthand engineers actually type. (3) Refusal threshold tuned on the new set.
What I'd do differentlyCollect real user questions before building and freeze the golden set before writing any retrieval code, so the test can't be shaped to fit the build.
Residual riskThe dictionary is hand-maintained. New shorthand will fail silently until it's added, so the weekly golden-set rerun in Project 3 is the control.

Decisions and why

DecisionAlternative rejectedReason
Extractive answers for the prototypeLLM-generated answersZero hallucination risk while validating retrieval. In aviation, a wrong answer costs more than a terse one.
Refuse below a confidence thresholdAlways answerA "don't know" routed to an engineer is safer than a confident wrong deferral limit.
Dictionary expansionEmbedding searchFixes the measured failure today with no infrastructure. Embeddings are the next iteration.

Estimation accuracy: calibrating plans against actuals

Most project plans are wrong in the same direction. Teams estimate the best case (the planning fallacy), and status stays "green" until it suddenly turns red. This tool takes a team's own estimate-vs-actual history and turns a new estimate into a calibrated P50/P80 forecast, the reference-class forecasting approach recommended in HM Treasury's Green Book guidance on optimism bias.
